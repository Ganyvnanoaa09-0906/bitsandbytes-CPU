# 灾难恢复指南（Data Recovery Guide）

> **适用范围**：`disk_balancer`（`--flash`）在**非受支持环境**（尤指 WSL）下使用，可能
> 导致的宿主 Windows 文件系统（NTFS / 主文件表 MFT）损坏与数据丢失。
>
> **前置条件**：请先阅读 `docs_cpu/QUICKSTART.md` §5 的「免责声明与使用限制」，确认
> 您处于**受支持环境**。本指南提供的是一般性恢复路径，**不构成对特定结果的保证**；
> 若涉及重要数据且您不确定，**应首选咨询专业数据恢复机构**。

> ##  必需：先准备一块「独立的存储介质」（U 盘 / 移动硬盘）
>
> **开始任何镜像/恢复前，必须准备一块【与受损盘不同物理磁盘】的独立存储介质**，
> 且其**剩余空间 ≥ 受损盘的总容量**（整盘镜像需要等大的空间）。
>
> **为什么必须独立物理盘**：镜像的目标**必须写在另一块物理磁盘上**，绝不能在
> 受损盘自身 / 与受损盘同一块的其它分区上。例如——**如果您的 C:/D:/E:… 全是同一块
> 物理 SSD 上的不同分区**，那么 U 盘 / 移动硬盘（独立物理盘）就是**唯一安全的目标**；
> 若您把镜像写到同一块 SSD 的另一个分区（如把 D 盘镜像到同一块盘的 E 分区），
> 相当于往正在损坏的盘上继续写数据，**会加剧损坏、且无法保护原始数据**。
>
> **可用的目标**：USB 闪存盘（U 盘）、外接移动硬盘、**另一块与受损盘不同的内置盘**
> （如在「磁盘管理 / diskpart → list disk」里能确认是**另一块 PhysicalDriveN**）。
> **绝不可用**：受损盘本身的其它分区 / 与受损盘同一物理盘的任何分区。
>
> **准备要点**：
> 1. 插上 U 盘 / 移动硬盘，容量 ≥ 受损盘总大小；
> 2. 用「磁盘管理（diskmgmt.msc）」或 `diskpart` → `list disk` 确认它确实是
>    **另一块物理盘**（不同 PhysicalDrive 编号），不是受损盘的分区；
> 3. 确认目标盘有足够的剩余空间，且可写。

---

## 一、诊断阶段：仅执行只读检查（勿修改数据）

数据损坏时，**唯一正确且安全的第一步**是**只读诊断**，**不修改磁盘**：

```
chkdsk <盘符>:          （不带 /f —— 只读报告，不修改数据）
```

- 若 `chkdsk` 报告 MFT / 文件系统错误 → 进入下一阶段恢复；
- **严禁**立即执行 `chkdsk <盘符>: /f`（会修改磁盘，可能将本可恢复的数据标记为丢失）；
- **严禁**对受损盘执行格式化 / 覆写 / 任何写操作。

> 在完成镜像或确认恢复方案前，**不要向受损盘写入任何数据**——哪怕一个字节都可能
> 覆盖 MFT 中待恢复的记录，造成不可逆损失。

## 二、第一梯队：自带的 `sector_mirror`

> **适用**：本仓库仍可用（含已编译的 `sector_mirror.exe` / `sector_mirror_gui.exe`）。
> 该工具使用 Win32 内核 API（`CreateFile` + `ReadFile`）**绕过文件系统**，直接读取磁盘
> **原始扇区**（`\\.\PhysicalDriveN`），将受损盘**整盘镜像**到一个**完好的驱动器**
> （如 U 盘）。**不依赖 Python**——即使 MFT 损坏导致 Python 无法运行，只要
> `sector_mirror.exe` 存在即可使用。
>
> 提供**两个版本**，内核完全相同（读原始扇区 + 稀疏镜像）：
>
> - **`sector_mirror_gui.exe`（GUI 版，推荐）**——纯 Win32 图形界面：**双击即用**，
>   下拉选「源盘」、点「浏览」选「目标镜像」、点「开始镜像」，进度条 + 日志，
>   **完全不需要命令行 / 传参**。当 `cmd.exe` / `powershell.exe` / `powershell_ise.exe`
>   因系统损坏而无法工作时，这是**最可靠**的入口（Win32 原生 GUI，不依赖任何 shell）。
> - **`sector_mirror.exe`（命令行版）**——在管理员命令行里指定源盘和目标镜像，
>   面向习惯脚本/批处理的用户。

### 2.1 编译（在完好的机器上）

```bat
:: 命令行版（VS x64 原生终端）
cl /O2 tools\sector_mirror.c /Fe:sector_mirror.exe /link advapi32.lib

:: GUI 版（依赖已由源码 #pragma 声明，无需手动 /link）
cl /O2 /utf-8 /DNOMINMAX /DNDEBUG tools\sector_mirror_gui.c /Fe:sector_mirror_gui.exe

:: 或 MinGW（命令行版）
gcc -O2 -o sector_mirror.exe tools\sector_mirror.c -ladvapi32
```

> **注意**：两版均为 Windows 专用（依赖 Win32 内核 API）。**命令行版已在本机
> （MSVC `cl`）编译通过并实测验证**：无参数列盘（列出盘符/容量/物理盘号）、
> 通过**源盘符**（如 `D:`）自动解析到物理盘、镜像到 U 盘、**稀疏镜像**（全 0 不占
> U 盘空间、非 0 数据保留）、进度显示——均正常。**实测用户反馈：测试没问题。**
> **GUI 版**同时编译通过，仅依赖 Windows 自带系统 DLL（`COMCTL32 / SHELL32 /
> COMDLG32 / ADVAPI32 / USER32 / GDI32 / KERNEL32`），静态 CRT，无 `vcruntime` 依赖。
> 不同系统/盘符组合请自行先小范围验证（尤其稀疏文件在 FAT32 移动盘上可能不受支持，
> 可改用 NTFS 移动盘以使用稀疏节省）。

### 2.2 使用（GUI 版，推荐 —— 无需命令行）

> 当 `cmd` / `powershell` 打不开时，**双击 `sector_mirror_gui.exe`** 即可，全部图形操作，
> 不需要敲任何命令、不需要传参数。

```text
1) 插好 U 盘（必须是【不同物理盘】，剩余空间 ≥ 源盘实际非 0 数据大小，建议 NTFS）；
2) 双击 sector_mirror_gui.exe（会自动弹出 UAC 授权提示，点「是」以获取管理员权限）；
3) 「源盘」下拉框选受损盘（如 D:）；「目标镜像」点「浏览...」选 U 盘文件名（如 d_drive.img）；
4) 点「开始镜像」；进度条走 + 日志滚动（可随时点「取消」，已写部分保留）；
5) 完成后，在完好机器上用 TestDisk / 7-Zip / winfr 从 .img 恢复。
```

- **自动提权**：双击即自动走 UAC 获得管理员权限（读原始盘需要），无需手动「以管理员运行」；
- **源盘下拉**：列出所有盘符 + 容量 + 所在物理盘号，直接选即可，无需记盘号；
- **目标浏览**：用系统「保存文件」对话框选目标镜像路径；
- **防二次损伤**：GUI 会校验目标不得为源盘 / 系统盘 `C:`；
- **进度条 + 日志**：实时百分比 + 逐条日志，可观察在复制；
- **可取消**：随时中断，已写部分保留（顺序文件，可续 / 可提取）。

### 2.3 使用（命令行版，管理员命令提示符）

> 工具支持**盘符选源**（推荐，傻瓜式）与**物理盘号选源**（旧版兼容）。

```bat
:: ① 先无参数运行，列出所有固定盘（含容量 + 所在物理盘号），帮你认出哪块是源盘
sector_mirror.exe

:: ② 用「源盘符」镜像（推荐）：把 D:（受损盘）整盘镜像为 E:\d_drive.img
::    （E: 必须是【不同物理盘】的 U 盘/移动硬盘，剩余空间 ≥ 源盘实际非 0 数据大小）
sector_mirror.exe D: E:\d_drive.img

:: ③ （旧版兼容）用「物理盘号」镜像：PhysicalDrive1 = 盘号 1
sector_mirror.exe 1 E:\d_drive.img
```

- **源盘符（推荐）**：如 `D:`——工具自动解析成 `PhysicalDriveN`（无需小白找盘号）；
- **无参数运行**：列出所有固定盘的盘符 / 容量 / 所在物理盘号，供你对照选择；
- **目标不得为源盘**：工具会校验（拒绝把镜像写向系统盘 `C:` / 与源盘同一物理盘 /
  物理设备路径），防止二次损伤；
- **稀疏镜像**：全 0 扇区写成「稀疏空洞」——**不占用 U 盘实际空间**（只占非 0 数据），
  非 0 数据全部保留（尽力保证完整，之后用恢复工具筛选）；
- **进度**：每 ~2 秒打印「扫描 X/Y MB，实际写入 Z MB [跳过全0块]」——可见在复制；
- **管理员权限**：读取原始盘 `\\.\PhysicalDriveN` 需要管理员权限；
- **Ctrl+C 中断**：已写入部分保留（可用于部分恢复）。

### 2.4 恢复（镜像完成后，在完好机器上操作）

- 使用 **TestDisk**（便携版）从 `d_drive.img` 恢复分区结构 / 文件；或
- 使用 **7-Zip** 提取 `.img`（若文件系统尚可读）；或
- 使用 **Windows File Recovery** 对镜像做深度扫描（`winfr` 支持从镜像恢复）。

### 2.5 签名恢复 `sector_carve`（自带，可干翻 winfr 的 signature 模式）

> **用途**：当 **MFT / 文件系统已损坏**、但**数据扇区还在**时，用【文件签名(magic bytes)】
> **绕过文件系统**直接从镜像/原始扇区里把仍完整的常见文件抠出来 —— 这是 **winfr 的
> signature 模式**做的事，但本工具**直接在已镜像的 `.img` 或原始扇区上做**，无需依赖
> winfr（也不用连微软商店）。**MFT 坏了 winfr 的 segment 模式反而不灵，而签名恢复此时最有效。**

```bat
:: 用法：sector_carve <镜像/盘符> <输出目录>（输出目录必须在另一块完好盘上）
:: ① 恢复你妈 U 盘的镜像（D:\usb_mom.img 是 sector_mirror 之前镜像的副本）—— 推荐
sector_carve.exe D:\usb_mom.img D:\carved_mom

:: ② 直接扫盘符（需管理员，且读原始扇区要求扇区对齐；建议优先用 GUI 版，或先镜像再扫）
::    —— CLI 直接扫物理盘时请确保扇区对齐；否则请用 sector_carve_gui.exe（内部已处理对齐）
sector_carve.exe E: D:\carved_mom
```

- **支持格式**：PNG / JPEG / GIF（图片）、ZIP（压缩包，自动识别 **docx/xlsx/pptx**）、
  PDF（文档）、MP4（视频）—— 流式跨块提取完整文件（不切碎）。见 `tools/sector_carve.c`。
- **GUI 版 `sector_carve_gui.exe`（推荐）**：**双击即用、无需命令行** —— 下拉选源盘、
  点「浏览镜像」选 `.img`、填输出目录、点「开始扫描」，进度条 + 日志 + 可取消。
  当 `cmd` / `powershell` 打不开时,这是最可靠入口(纯 Win32 GUI,同 sector_mirror_gui)。
- **零写入原盘**：建议先 `sector_mirror` 镜像，再在镜像（普通 .img）上跑 carve，最安全；
- **输出目录禁止写回受损盘**；
- **恢复结果**：文件按 `carved_NNNNNN.<ext>` 编号命名，需再用看图/解压/播放器确认可用性
  （carve 只还原字节内容，不重建文件名/路径，这一点与 winfr 的 segment 模式一致）。

> **实测参考**：对一块 **MFT 已损坏、Windows 打不开的 U 盘**（7.5GB，**PhysicalDrive1**），
> ① `sector_mirror` 整盘镜像到 `D:\usb_mom.img`；② 用 `sector_carve` 扫镜像，恢复出
> **3200+ 个文件**（jpg/png/gif 照片、zip/PDF/MP4、**Word/Excel/PPT docx/xlsx/pptx**）。
> 抽样验证：PNG 99.6% 可打开、**docx 10/10 / xlsx 5/5 / pptx 1/1 有效 OOXML**、MP4 完整
> `ftyp/moov/mdat`、含 4032×3024 的 12.2MP 真实照片。
> **GUI 版也已实测**：直接选 `E: (PhysicalDrive1)` 扫物理盘（内部已做扇区对齐，绕过坏
> 文件系统），恢复出的文件 **约 95% 可正常打开**（少量打不开的是签名恢复常见的误报/
> 碎片截断 —— 任何签名恢复工具都如此，winfr 亦然）。**说明在文件系统损坏时，签名恢复
> 能绕过 MFT 找回照片/文档/压缩包/视频，GUI 双击即用、不依赖 cmd/winfr。**

## 三、第二梯队：连本仓库/工具都不可用时 → Windows File Recovery

> **适用**：**MFT 损坏过于严重，连本仓库 / Python / exe 都无法运行**。退回
> *在微软商店下载 Windows File Recovery*
### 3.1 使用（管理员命令提示符）

```bat
:: 深度扫描 D 盘，恢复全部文件到 E:\recovered（E 为另一块完好盘）
winfr D: E:\recovered /extensive /n *

:: 仅恢复特定目录/文件（如项目代码、训练数据）：
winfr D: E:\recovered /extensive /n \那很有乐子了~  /n 训练脚本
```

- **输出必须写入另一块盘（E）**，**严禁写回受损盘（D）**；
- `/extensive` 为深度扫描——MFT 损坏时找回概率更高；
- 更多用法：`winfr /?`。

---

## 四、防二次损伤要点（务必遵守）

1. **恢复完成前，禁止向受损盘写入任何数据**；
2. **优先镜像（第一梯队）再操作**——在完好副本上恢复最安全；
3. 数据恢复工具（TestDisk / PhotoRec / winfr）**应从另一块盘运行，输出写另一块盘**；
4. 若不确定 / 涉及重要数据，**先只读 `chkdsk` 诊断，并咨询专业人员**。

---

## 五、结论陈述

- 若按上述路径**恢复成功**：数据可找回，请按本指南操作；
- 若**恢复失败**（MFT 损坏过深 / 扇区已被覆写）：**损失数据可能无法恢复** —
  请**以备份 / 镜像为准**，**切勿在受损盘上反复尝试覆写类操作**（只会加剧损坏）。

> **最后提醒**：任何数据恢复操作都存在不确定性。若数据价值较高，**请优先采用
> 专业数据恢复服务，而非自行反复尝试**。
